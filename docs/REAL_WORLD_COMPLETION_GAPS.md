# Real-world product implementation audit (2026-10-16)

The existing authenticated `/live` CSV path and isolated `/demo` were retained. The live path now includes provider reads, versioned observations, source-linked incidents, and simulations built from observed business records.

| Area | Implemented and locally checked | Remaining external verification or limit |
| --- | --- | --- |
| Shopify | Standalone OAuth state and HMAC checks; encrypted offline token handling; pinned Admin GraphQL read sync for variants, stock, orders, returns and refunds; nested cursor pagination; optional approved `read_all_orders` request; initial and manual incremental reads; verified and deduplicated webhooks; retry worker; status, disconnect, uninstall and shop redaction. Mocked provider and signed webhook tests. | Authorize a real development store and exercise configured webhooks and pagination. Default order scope has a limited historical window; older access requires approval and reauthorization. A top-level or nested connection over 10,000 records fails explicitly. |
| Observed twin | Versioned snapshot at a selected ingestion cutoff, coverage/consistency report, adjustable estimates and disruption, three deterministic branches, stored event replay, plan review and sandbox verification. Source projections are compared before and after replay. | History starts at first ingestion. Live and synthetic demo simulations use separate domain engines. Forecasts are estimates. |
| History | Source observations with provider/object IDs, schema version, external and ingestion times, idempotency key, causation/correlation and previous version references; audit and source explorer. A PostgreSQL trigger rejects observation updates and deletes, except the transaction-scoped Shopify privacy-redaction path. The migration, trigger and redaction path passed on PostgreSQL 14. | Privacy redaction deliberately erases Shopify material. Managed PostgreSQL failover remains unverified. |
| Razorpay | Encrypted credentials after successful read-only authentication; payments, refunds, settlements and reconciliation line retrieval; exact paise arithmetic; overlapping manual or Compose-scheduled polling; dense historical time-window partitioning; persisted reconciliation-day backlog; signed and deduplicated webhook receiver with a per-connection encrypted secret and retry; bank CSV linkage; discrepancy detection; source references and status. Mocked adapter and signed webhook tests. | No credentials were available for a real test-account sync or webhook delivery. Merchant dashboard subscription is required. The Compose worker has not been run here because Docker was unavailable. Provider retention, live endpoint limits and completeness remain unverified. |
| Incidents and AI | Persisted source-backed discrepancies, typed read tools, deterministic checks, optional bounded model interpretation with source/figure/action validation, policy-gated recovery options, review and auditable conclusion. | Without a model endpoint, the investigator uses the labeled deterministic fallback. AI answers are advisory and no external write action exists. |
| UX and end-to-end | Workspace selection, provider controls, CSV import, source drill-down, Money Trail, observed history, agent traces, three-branch comparison, review, replay and verification; the synthetic demo remains separate. | Provider-connected browser journeys require merchant credentials and external subscription setup. Public deployment requires security and concurrency hardening described in the README. |

Local checks include Alembic migrations and runtime tests on PostgreSQL 14 in WSL, SQLite contract tests, a Next.js production build, and Playwright against the real API and PostgreSQL. Docker was unavailable. No Shopify, Razorpay or model credentials were present. These checks establish application behavior, not successful live provider connectivity. See [validation and limitations](VALIDATION_AND_LIMITATIONS.md).
